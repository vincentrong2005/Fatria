# 正文互通智脑项目计划

> 这是一个只写计划和架构判断的项目文件，不写新剧情、不写正文内容、不写实际实现代码。目标是把「小手机」的正文互通能力和「明月秋青脚本」的智脑压缩/注入思路合成一个更专注的正文增强项目。

## 1. 我对小手机正文互通的理解

小手机的核心不是单纯 UI，而是一套「正文与外部模块互相喂信息」的桥。

正向：正文进入手机
- 世界书提示词要求 AI 在正文自然位置输出短标签，例如 `<闪讯 from="角色名">摘要</闪讯>`、`<话圈 author="角色名">标题</话圈>`、`<吃点啥>配送摘要</吃点啥>`。
- `content-capture.ts` 用 `CAPTURE_PATTERNS` 捕获这些标签，抽成 `CapturedEvent`。
- `index.ts / 澜景市版.ts` 在 `MESSAGE_RECEIVED` 监听 assistant 楼层，只处理 AI 输出。
- 捕获后先用 `stripPhoneTags()` 从正文删掉标签，再用 `setChatMessages()` 回写干净正文，避免标签污染阅读。
- 每个捕获事件会进入 `processCapturedEvent()`，再走 `generateForApp()`，由对应 APP 内置预设把「摘要」扩展成完整手机内容，并写入 IndexedDB 和手机状态。
- 特殊社交标签如 `<闪讯好友>`、`<闪讯拉黑>`、`<闪讯删好友>` 不走普通 APP 生成，而是直接改好友/拉黑状态，再从正文移除。

反向：手机操作进入正文
- 各 APP 调用 `store.reportAction()`，只把操作先放进 `pendingActions`，不实时刷到正文。
- 闪讯聊天还会进入 `pendingChatLogs`，保留完整聊天记录。
- 用户关闭手机时，`App.vue` 监听 `store.isOpen` 从 true 变 false：
  - 把所有操作按金融/社交/浏览/其他分类。
  - 用 `generateForApp('summary')` 生成不超过三句的自然语言总结。
  - 拼上完整聊天记录，用 `createChatMessages()` 写入一条 user 楼层：`📱 手机操作：...`。
  - 同时调用 `indexPhoneSessionMemory()`，把这次手机会话变成可召回记忆块。
- 世界书的「用户手机操作说明」会告诉正文 AI：看到 `📱 手机操作` 时要自然消化，不要复述机制，不要让无关角色全知。

生成前记忆回灌
- 小手机在 `GENERATION_AFTER_COMMANDS` 事件中读取最近 3 层聊天作为 query。
- `getMemoryInjectContext()` 从本地 IndexedDB 的 memory chunks/向量召回相关手机记忆。
- 用 `injectPrompts([{ position: 'in_chat', role: 'system', depth: 2 }], { once: true })` 临时注入到下一次正文生成。
- 这让正文能记得手机内发生过的事，但不会把所有手机历史全塞进上下文。

模块化内置预设
- `preset-store.ts` 的 `APP_PRESETS` 是关键模式：每个 app 有 `appId / contextLevel / outputFormat / systemPrompt / maxChatHistory / formatDescription`。
- `buildOrderedPrompts()` 按 `full / medium / light` 三档组装 ordered_prompts：完整角色上下文、轻量世界观、纯工具输出分开。
- `generation-pipeline.ts` 用 `generateRaw({ custom_api, ordered_prompts, max_chat_history, should_silence })` 独立调用，不污染正文预设。
- 这套可以直接抽象成「模块预设注册中心」，不仅用于手机 APP，也可用于总结、记忆、正文桥接、格式修复等内置任务。

## 2. 我对明月秋青智脑压缩思路的理解

智脑的核心是「捕获正文 -> 结构化总结 -> 隐藏旧楼层 -> 精准注入有效记忆」。它不是单纯把上下文缩短，而是把旧正文转成可控的记忆层。

正文捕获
- `index.ts` 监听 `MESSAGE_RECEIVED` 和 `MESSAGE_SWIPED`。
- 优先提取 `<content>...</content>`，没有就剥离 `<think>` 后取全文。
- 还会把 `<time>` 或正文时空栏前置到捕获内容里，方便后续按剧情时间总结。
- 每条捕获记录保存 `messageId / content / capturedAt / swipeCount`。
- 同时记录前一条 user 输入与当前 AI 正文，用于梦呓分析和 roll 偏好。

自带总结与压缩
- `shouldTriggerSummary()` 不是一满 N 条就全总结，而是保留最新 4 条 AI 发言不总结，避免刚发生的剧情被过早压扁。
- `executeGrandSummary()` 使用 `generateRaw()` 自建 ordered_prompts：破限头、角色分析体系、总结任务指令、输入材料、assistant prefill。
- `max_chat_history: 0`，只给它明确整理材料，避免正文预设和聊天历史干扰总结任务。
- 输出被强制分为：剧情摘要、角色第一人称记忆、动态人设、NSFW 隔离记录。
- `addSummary()` 把第一次总结的记忆转成核心记忆；后续总结保留核心，新增近期，近期只滚动保留。
- 总结成功后 `hideCapturedContentsWithUsers()` 会隐藏已总结 AI 楼层和对应 user 楼层，同时 `ensureRecentFloorsVisible()` 保证最新楼层不被隐藏。

提示词插入技术
- `CHAT_COMPLETION_SETTINGS_READY` 是成熟插入点：此时可以直接改 `completion.messages`，也可以调用 `injectPrompts()`。
- 大总结只注入第一部分剧情摘要，用 `<grand_summary>` 包裹；角色记忆不全量注入，交给神经链按在场角色激活。
- 用户人格注入采用直接 splice 消息数组：优先找 `<深度2>`，找不到就找 `</chathistory>` 或 `</additional_settings>`，最后才兜底插入。
- 动态人设、神经链、情绪、倒果为因等用 `injectPrompts()` 独立管理，每次先 `uninject()` 旧内容再注入新内容，避免叠加污染。
- 梦呓不是 system 注入，而是包到最后一条 user message 前面，让模型把它当「用户行为模式背景」消化。

神经链第一人称记忆
- 大总结要求角色记忆必须用第一人称，而且按角色态度产生不同记忆偏差：喜欢会美化、厌恶会歪曲、中立会模糊。
- `CharacterMemory` 保存 `characterName / aliases / attitude / coreMemories / recentMemories / keywords`。
- `injectNeuralChain()` 先扫描最新正文出现的角色名和别名。
- 只激活当前在场角色的记忆，并按链路组织：用户与角色、角色与角色。
- 这样正文不会被全角色记忆淹没，只把当前场景相关的记忆递给模型。

## 3. 新项目定位

项目暂名：`正文神经桥`

一句话目标：
在不改正文创作主体的前提下，增加一个可捕获、可总结、可压缩、可回灌的外置智脑层，让正文既能和模块互通，又能长期保持角色记忆质量。

这个项目不是新正文生成器，也不是新剧情库。它只做：
- 捕获正文里的结构化事件。
- 捕获用户在模块里的操作。
- 自动总结旧正文，隐藏可压缩楼层。
- 以神经链方式把角色第一人称记忆注入下一次生成。
- 用模块化内置预设处理所有内部任务。

## 4. 功能拆分

### A. 正文互通桥 `contentBridge`

职责：
- 监听 assistant 楼层，捕获项目标签。
- 清理正文中的系统标签，保持聊天区可读。
- 把标签事件写入模块事件库。
- 监听用户模块操作，关闭/提交时写回 user 楼层。

计划格式：
```xml
<正文桥 type="event" module="模块名" actor="角色名">
一句摘要，不写完整正文
</正文桥>
```

原则：
- 标签内容只写摘要，不重复正文。
- 标签捕获后必须清理。
- 用户操作写回正文时用自然总结，不暴露内部 JSON。
- 与正文互通只走「短摘要 -> 模块扩展」和「操作总结 -> 正文消化」两条路。

### B. 自带总结 `summaryCore`

职责：
- 保存捕获正文日志。
- 按间隔触发总结，默认排除最新 4 条 AI 发言。
- 使用独立 `generateRaw()` 和项目内置总结预设。
- 输出：剧情摘要、角色记忆、动态人设、可选隔离记录。
- 总结后隐藏已覆盖楼层，保留最近楼层可见。

输出约束：
- 禁止创作新内容，只整理已有信息。
- 剧情摘要客观白描，保留关键对话原文。
- 角色记忆必须第一人称。
- 每条记忆带剧情时间和层级：`[核心]` 或 `[近期]`。

### C. 神经链记忆 `neuralMemory`

职责：
- 从总结中维护角色记忆库。
- 保存别名、态度、关键词、核心记忆、近期记忆。
- 扫描当前正文/最后用户输入，识别在场角色。
- 只注入相关角色的记忆链。

注入形态：
```xml
<neural_chain>
<memory_chain_user_角色名>
角色名对用户的第一人称记忆：
[核心记忆]
- ...
[近期记忆]
- ...
</memory_chain_user_角色名>
</neural_chain>
```

规则：
- 不在场角色不注入。
- 多角色同场时再扫描交叉记忆。
- 记忆不改写为上帝视角，保持角色第一人称原味。
- 有冲突时近期记忆影响行为，核心记忆影响底层态度。

### D. 提示词装配 `promptAssembler`

职责：
- 统一管理内部任务的 `ordered_prompts`。
- 统一管理正文生成前注入。
- 提供三种插入方式：
  - `injectPrompts()`：适合大总结、动态人设、神经链。
  - `completion.messages.splice()`：适合精准插入到 D2、聊天记录结束后。
  - last user 包裹：适合用户行为模式、模块操作背景。

推荐插入层级：
- 大总结：`position: 'in_chat', depth: 8, once: true`。
- 神经链：`position: 'in_chat', depth: 0-2`，每次先卸载旧注入。
- 动态人设：`position: 'in_chat', depth: 0`。
- 模块记忆：`position: 'in_chat', depth: 2`。
- 用户行为模式：直接前置到最后一条 user message。

安全策略：
- 每个注入块必须有稳定 id。
- 每次请求前刷新，不长期堆叠。
- 不把内部总结任务的提示词注入正文。
- 内部任务 `max_chat_history` 默认 0，只读明确输入材料。

### E. 模块化内置预设 `modulePresetStore`

借小手机 `APP_PRESETS` 的方式，但抽象为任意模块。

数据结构：
```ts
interface ModulePreset {
  moduleId: string;
  label: string;
  contextLevel: 'full' | 'medium' | 'light';
  taskType: 'summary' | 'expand' | 'repair' | 'memory' | 'bridge';
  outputFormat: 'xml' | 'json' | 'text';
  maxChatHistory: 'all' | number;
  systemPrompt: string;
  parser: string;
}
```

首批内置模块：
- `bridge_event_expand`：把正文桥标签扩展成模块事件。
- `phone_action_summary`：把用户操作总结成正文可消化文本。
- `grand_summary`：大总结。
- `character_memory_extract`：角色第一人称记忆解析/修复。
- `dynamic_profile_update`：动态人设更新。
- `prompt_repair`：当 XML/分段输出坏掉时修复格式。

## 6. 一轮生成前后的完整流程

1. 用户正常发言，或模块在关闭时写入 `📱/模块操作` user 楼层。
2. 正文 AI 生成，世界书允许它在自然位置写 `<正文桥>` 或具体模块标签。
3. `MESSAGE_RECEIVED` 后：
   - 捕获正文内容。
   - 捕获模块标签。
   - 清理标签并回写干净正文。
   - 事件入库。
   - 记录 user 输入与 AI 正文。
4. 如果达到总结间隔：
   - 排除最新 4 条 AI 发言。
   - 用内置 `grand_summary` 预设总结旧正文。
   - 更新角色第一人称记忆和动态人设。
   - 隐藏已总结楼层与对应 user 楼层。
5. 下一次 `CHAT_COMPLETION_SETTINGS_READY`：
   - 注入大总结摘要。
   - 扫描在场角色。
   - 注入神经链记忆。
   - 注入动态人设。
   - 注入模块相关记忆。
6. AI 看到的是压缩后的高质量上下文，而不是又长又散的旧正文。

## 7. 我会优先落地的 MVP

MVP 不做复杂 UI，只做稳定内核。

第一阶段：正文互通
- 新建项目骨架。
- 实现标签捕获、清理、事件入库。
- 实现用户操作缓冲和关闭/提交时写回正文。
- 写两份世界书规则。

第二阶段：自带总结
- 捕获正文日志。
- 手动触发总结。
- 输出三段：剧情摘要、角色记忆、动态人设。
- 保存到聊天变量。

第三阶段：压缩楼层
- 自动触发总结。
- 隐藏已总结楼层。
- 保留最新 4 条 AI 发言和对应 user 楼层。
- 面板或控制函数支持恢复。

第四阶段：神经链注入
- 解析角色记忆。
- 扫描在场角色和别名。
- 只注入相关角色第一人称记忆。
- 与大总结摘要分层注入。

第五阶段：模块化预设
- 抽象 `ModulePreset`。
- 把总结、桥事件扩展、操作总结、格式修复都改成内置预设。
- 设置页后续再开放编辑。

## 8. 关键取舍

- 不把所有记忆塞进正文，只按当前场景激活。
- 不实时把每个模块操作写成 user 楼层，先缓冲再总结，减少噪音。
- 不让总结吃当前最新剧情，最新 4 条保持原文可见。
- 不把正文标签留在聊天区，捕获后清理。
- 不让内部任务走正文预设，内部总结和扩展任务独立 `generateRaw()`。
- 不写新内容，只整理、压缩、注入、互通。

## 9. 我认为最重要的质量点

1. 总结必须稳：格式坏了要能修复，不能因为一次输出失败毁掉记忆库。
2. 记忆必须像角色本人：第一人称、带偏差、带态度，不要变成客观百科。
3. 注入必须少而准：当前场景用谁就注入谁，不做全量背景轰炸。
4. 正文必须干净：标签只作为机器通道，用户看到的是自然正文。
5. 模块预设必须可扩展：以后新增模块只加 preset、parser、registry，不动主流程。

## 10. 最终判断

这个项目最适合做成「正文外置智脑层」。
小手机提供互通和模块预设范式，明月秋青提供压缩、总结、神经链和注入范式。两者合起来，最有价值的不是再造一个大 UI，而是做一个低干扰、高召回、会自己压缩上下文的正文增强底座。
