# 性斗学园脚本发布规则

每次发布必须使用不可变 Git 标签，不再把 `main` 当作用户更新目标。脚本版本、更新清单版本和 Git 标签必须是同一个
`X.Y.Z`，例如三者分别为 `3.6.11`、`3.6.11`、`v3.6.11`。

1. 选择一个大于现有所有发布标签的新版本 `X.Y.Z`，且确认远端不存在 `vX.Y.Z`。
2. 将 `scriptUpdater.ts` 中的 `SCRIPT_VERSION` 更新为 `X.Y.Z`。
3. 将 `update-manifest.json` 的 `version` 更新为相同的 `X.Y.Z`，并将 `releaseTag` 更新为 `vX.Y.Z`。
4. 推送源码和更新清单到 `main`，不要手动创建或删除发布标签。
5. `bundle` 工作流构建产物后，会在该产物提交创建
   `vX.Y.Z`；它会校验脚本版本、清单版本与标签一致，不会自动递增版本，也不会删除旧标签。
6. 等待工作流完成，并确认 jsDelivr 的 `@vX.Y.Z` 脚本 URL 可访问后，再通知用户更新。

设置页的“更新至 vX.Y.Z”只会修改当前角色脚本库中、与当前脚本 ID 对应的官方 jsDelivr 导入地址。它会把 `@main`
或旧发布标签替换为 `@vX.Y.Z`，随后刷新页面。即使脚本代码已是最新版本，只要仍使用
`@main`，也会提供固定版本操作。非官方链接、内联脚本、标签不存在或不在角色脚本库中的脚本不会被修改。
